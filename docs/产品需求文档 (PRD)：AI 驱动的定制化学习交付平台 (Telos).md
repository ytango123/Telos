# 产品需求文档 (PRD)：AI 驱动的定制化学习交付平台 (Telos)

## 1. 执行摘要
Telos 旨在重新定义 AI 在教育技术（EdTech）中的角色。当前市场上的 AI 工具多聚焦于**信息检索**或**知识库管理**，以帮助AI更好的管理知识，然后对于用户而言，并没有帮助用户实现真正的认知提升。本产品通过**目标驱动的自动化教学设计**，将碎片化的用户输入转化为结构化、多模态且开箱即学的定制化学习课程。其核心使命是消除从“获取信息”到“内化知识”之间的摩擦力，为用户提供极致丝滑的学习体验。

---

## 2. 核心价值主张与市场定位
Telos 的核心竞争力在于其**交付物形态**。它不提供零散的对话回复或是学习路线指南等，而是交付一个包含完整学习内容的、具备专业 UI 审美的**学习工作站**，用户可以直接开始学习。

| 维度 | 传统 AI 助手 (Chatbot) | 知识库工具 (PKM) | Telos |
| :--- | :--- | :--- | :--- |
| **交付形态** | 线性对话流 | 树状/网状文档 | 结构化课程工作站 |
| **用户参与度** | 需不断提问引导 | 需手动整理分类 | 提交目标后异步交付 |
| **内容深度** | 随机且受限于 Prompt | 取决于用户搜集能力 | 目标驱动的深度定制 |
| **多模态集成** | 简单图片/文本 | 附件挂载 | 深度融合的交互式组件 |

---

## 3. 用户痛点深度对标
本产品精准解决用户在现代碎片化信息环境下的三大核心痛点：

> **痛点一：灵感与问题的瞬时性与易逝性**
> 用户在平日可能突然想到一些问题，但不一定有时间马上解决，如果搁置有可能会遗忘；Telos 通过“备忘录式”的 Block 捕获机制，允许用户随时随地记录自己的问题。

> **痛点二：资料搜寻与筛选的“重体力活”；跨平台查阅的碎片化学习打破专注**
> 跨平台（如小红书、CSDN、Arxiv）的资料搜集耗费了用户 70% 的学习时间。本产品利用 AI Agent 自动执行跨平台检索、去重、质量评估与逻辑排序整合。同时最终直接将爬取到的图片、视频、甚至动画等渲染嵌入在平台的页面中，而不需要用户跳转各个平台查阅分散他们的注意力。

> **痛点三：学习内容与实际目标的脱节**
> 同样的知识点，在“广泛涉猎不要求深入”/“彻底搞懂底层原理”/“应对面试准备”/“学术研究”等场景下的侧重点完全不同。Telos 引入“目标配置层”，确保生成的每一行内容都精准命中用户需求。

## 4. 核心功能模块详述

### 4.1 智能捕获与情境配置层
用户通过极简界面创建 **Learning Block**。每个 Block 不仅是一个记录框，更是一个**情境容器**。用户可以挂载多种自己已有的 Source（如 YouTube 链接、PDF 论文、播客音频，这里可以参考Notebooklm），并设定明确的 **Learning Target**。

- **目标驱动引擎**: 用户可定义最终交付的预期，例如“能在面试中深入浅出地解释 Transformer 机制”或“快速掌握 React Server Components 的基本用法以进行项目开发”。
- **源偏好设置**: 支持指定偏好来源（如小红书、知乎、YouTube、CSDN、arxiv）等等

### 4.2 异步 AI 教学设计流
一旦用户提交 Block 或 Group，后台 AI Agent 将启动多阶段工作流。实时进度可视化。

1. **多维检索 (Multi-Source Retrieval)**: 结合实时网络搜索，覆盖学术、技术社区及社交媒体。
2. **知识解构与重组 (Deconstruction & Synthesis)**: AI 将获取的信息拆解为原子知识点，并根据用户目标重新编排逻辑架构。
3. **多模态生成 (Multimodal Generation)**: 
    - **文本层**: 撰写结构化的综述与深度解析。
    - **视觉层**: 自动生成 Mermaid 流程图、SVG 交互动画或 Canvas 图解。
    - **资源层**: 筛选并嵌入最高质量的第三方视频/图片资源。

### 4.3 沉浸式学习工作站 (The Learning Station)
交付的学习界面采用**章节化布局**，旨在提供一种“开箱即学”的沉浸感。

- **结构化导航**: 左侧动态生成的章节目录，支持逻辑跳转。
- **交互式笔记系统**: 参考 theMoonlight 的AI交互逻辑，支持做笔记、划重点、AI 追问。
- **动态调整机制**: 用户可以对生成的方案进行“微调”，如要求 AI “针对第三章增加更多代码实例”或“简化第二章的数学推导”，亦可自己编辑/添加内容。

## 6. 技术实现路径概要
为了实现上述功能，系统需构建在强大的 AI 编排层之上。详见 [技术选型文档](./技术选型.md)。

### 核心技术栈
- **模型层**: 采用 **DeepSeek V4 Flash** 作为主力模型（成本约为 Claude/GPT-4o 的 1/20），支持 1M 上下文窗口
- **Agent 框架**: 采用 **LangGraph** 处理多 Agent 异步编排（检索、生成、规划、多模态）
- **前端架构**: 使用 **Next.js 16** (App Router) + **Tailwind CSS 4** + **shadcn/ui**，内容渲染使用 **Shiki** + Fumadocs UI 组件，富文本编辑器 **Lexical（规划中，当前为 Markdown + Textarea）**
- **数据存储**: 第一期采用本地方案（**SQLite** + **LanceDB**），后期可迁移云端

### 阶段规划
1. **Phase 1 (MVP)**: Block 创建 + 基础内容生成 + 章节化展示
2. **Phase 2**: 多 Agent 编排 + 多源检索 + RAG
3. **Phase 3**: 交互笔记 + 多模态生成
4. **Phase 4**: 云端迁移 + 模型升级（可选）

## 7. 结论
Telos 不仅仅是一个工具，它是一种全新的**认知加速器**。通过将 AI 的能力从简单的“问答”提升到“系统化交付”，它真正解决了用户在信息爆炸时代的学习焦虑，实现了从“知道”到“理解”的跨越。
